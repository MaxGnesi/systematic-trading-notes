# Systematic Trading Notes

Lecture notes on systematic trading (MSc level). Each lecture lives in its own folder together with
the notebook that tests its claims on real market data and the charts it cites.

## The course at a glance

**In one sentence.** Build simple trading rules on reasons that should last, judge them against luck and on data they were not built on, count every try, and expect what such rules can honestly deliver.

**What it teaches.** The base layer of systematic research. First, the core cross-asset styles, **trend, carry and value**, built from free data across currencies, commodities, bonds and equities, tested honestly and combined into a portfolio judged as an addition to an ordinary portfolio of stocks and bonds. Second, a deeper dive into **higher frequency**: the tape and the order book, where trading costs are decided and where short-horizon edges live or die. The base layer is what every systematic portfolio starts from; the deeper parts show where more breadth, finer granularity and better execution come from. Along the way it teaches the research method itself, including how to work with an AI assistant without fooling yourself (Lecture 17), and it ends by running a trend rule live (Lecture 24).

Part V is a deep dive on purpose, and a first hands-on with tick and order-book data: the same tools let a live strategy check its execution against the market at the moment of each order. It uses bitcoin tick and order-book data, the one market where such data are free at that depth, to set the stage for the analysis one should also do on traditional markets: it is an example and the beginning of a direction. Its lessons on execution matter for the base layer too: a daily portfolio is still traded order by order, and its costs decide whether a small edge survives.

### How every lecture works

- **The plan comes first.** Hypotheses, rules and expectations are written down and dated before any result; every change made after seeing results is dated and labelled (`results/hypotheses.md` in each lecture folder).
- **Luck is the yardstick.** A strategy is compared with many random strategies of the same kind; a filter with random switching that keeps trend off just as often.
- **Data not used to build it.** Every result that matters is checked on a period or a dataset the choice was not made on.
- **Every try is counted.** The best of many versions looks better by luck; the deflated Sharpe ratio corrects for the search.
- **Evidence is weighed, not passed.** Lasting edges are small and noisy; a result is judged on its probability, its breadth, a reason it should persist and what it adds, not on one threshold.
- **Published versions are the check.** Where a strategy has a published construction, ours is compared with it, and every difference is shown with what it costs.
- **Every lecture has its place in the pipeline.** Each names its stage (data, signals, allocation, risk, execution, or the research loop), so it is clear what it builds and where it fits (Lecture 1 §2.1).
- **Every claim can be rerun.** Each lecture's notebook redraws its figures and checks its mechanics by hand on the same data.

### What the course found

| Finding | Where |
|---|---|
| Trend following on many markets earns a Sharpe ratio of about 0.5 to 0.7 after costs, on ETFs and on futures, over decades | Lectures 12-13, 16 |
| Regime switches give promising leads well beyond chance, none yet a rule: the strongest ran against the plan (trend did worse after large dollar moves, beating 94% of random switches on untouched years) | Lecture 14 |
| Carry across currencies, commodities, bonds and equities adds to trend; its edge is sensitive to trading costs and paid for with sudden losses | Lectures 15-16 |
| Value measured by price alone lost in this period; value from fundamentals earned a little | Lecture 15 |
| Short-horizon strategies live or die by execution: speed, queue position and the traders on the other side | Part V |
| Trend and carry together can be expected to earn about what a stock-and-bond portfolio earns per unit of risk, with a correlation to it near zero; a modest share of an investor's risk lifts the whole portfolio | Lecture 16 |
| Higher Sharpe ratios come from breadth and better execution added on top of a fixed base, not from a cleverer version of the same few signals | Lecture 16 |
| In this course's own record, every error that reached a result was silent (the code ran, the numbers looked plausible); the costly ones were design choices found by a reviewer, not bugs | Lecture 17 |

**Where to take it next.** The base layer stays fixed, and each of seven research directions changes one part of what we built: how it trades (cheaper execution), how much trend it holds (regime information as a tilt), which markets it holds (more breadth), a new sleeve beside it (a faster horizon), its weights (construction that uses only what is known), when it trades (kill switches from the book and the flow), and the assumptions behind it (the live strategy against its backtest). Each is an open question with the lecture that sets it up: [Lecture 16 §8.2](lectures/16-the-final-portfolio/lecture.md).

### What you will be able to do

- Build a strategy end to end, from raw data to positions, costs and a portfolio.
- Test it honestly: against luck, on data it was not built on, counting the tries.
- Read a market below the bar: trades, order flow, the order book and what execution costs.
- Combine small, robust edges into a portfolio, and set realistic expectations for it.
- Work with an AI assistant fast and with discipline: lock the scope and the tests, log every try, verify what comes back.
- Run a rule live and check its fills against the market and the backtest.

**What you need.** Python and pandas, statistics at the level of a first course (regression, standard errors), a computer with about 8 GB of free memory for Part V. All data are free; none are committed to the repository (see each lecture's notebook for the downloads).

**Not covered.** Single-stock factor investing, options, cross-exchange market making (the free archives do not hold both venues' books for our period) and prediction markets.

The roadmap and the style and formula conventions for writing the notes are in [COURSE_GUIDE.md](COURSE_GUIDE.md).

### How these notes were made

These notes were written with an AI assistant (Claude, by Anthropic). The course design, the research questions, the expectations fixed before each test, and the judgment on methods and results are the author's. The assistant wrote most of the code, ran the analyses, drafted the text and checked references, under that direction and review. Several of the course's key choices came from the author's corrections of the assistant's first proposals: comparing bonds across countries, measuring equity carry from earnings, building value from fundamentals, weighing evidence instead of using fixed significance thresholds, and setting realistic expectations. Every plan was fixed and dated before its results (`results/hypotheses.md` in each lecture), every number can be rerun from the notebooks, and errors found later are corrected with dated notes. A lecture on research with AI (planned as Lecture 17) describes this process: what an assistant speeds up, and where it needs a human check.

## Layout

```
lectures/
  01-introduction/
    lecture.md, lecture.docx
  02-ohlcv-and-price-smoothing/
    lecture.md
    02_price_smoothing.ipynb
    figures/                     PNG charts cited by the lecture and written by the notebook
  03-same-bars-different-questions/
    lecture.md
    03_same_bars_different_questions.ipynb
    figures/
trading_models/                  shared Python package the notebooks import
data/raw/                        price cache, created on first run (git-ignored)
```

`trading_models/` stays at the root because it is shared: both notebooks import it, and later
lectures will too. It is the minimal subset of a larger private research project needed to run
these notebooks (traced by import, not hand-picked). Where a technique already has a tested
implementation there (Kaufman's Adaptive Moving Average, the Kalman filter, Wilder's ATR, ADX and
efficiency ratio), the notebooks import it rather than reimplementing it, and each notebook checks
its hand calculations against the package on a real date.

The notebooks are committed with their outputs, so tables and charts are visible on GitHub without
running anything. Charts are embedded as static PNGs; running a notebook regenerates them, together
with interactive HTML versions (git-ignored), in its lecture's `figures/` folder.

## Running the notebooks

```bash
python -m venv .venv
.venv\Scripts\activate          # .venv/bin/activate on macOS/Linux
pip install -r requirements.txt
pip install -e .
jupyter lab lectures/
```

Each notebook finds the repository root by looking for `pyproject.toml`, so it can be run from any
folder. PNG export needs a Chromium-based browser (Chrome or Edge) installed; without one, only the
HTML charts are written.

No price data is bundled. The notebooks fetch daily bars from Yahoo Finance on first run (via
`yfinance`) and cache them under `data/raw/`, which is git-ignored. This is deliberate: Yahoo
Finance's terms generally restrict redistributing its data, so re-running the notebooks is the way
to get it.
